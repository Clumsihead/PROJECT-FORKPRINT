# Forkprint Philosophy

> *"People don't remember restaurants. They remember experiences."*

---

# Why Forkprint Exists

Forkprint exists to quietly preserve one of the most overlooked parts of everyday life:

Food memories.

People remember birthdays, celebrations, road trips, first dates, late-night snacks, family dinners, hidden cafés, vacations, and favorite comfort food.

Unfortunately, those memories slowly disappear.

Restaurant names are forgotten.

Locations are forgotten.

Dates blur together.

Forkprint exists so they don't have to.

Forkprint quietly remembers those experiences and allows people to rediscover them years later.

The product is not about restaurants.

It is about memories.

---

# Our Mission

Build the world's most personal food journal.

Not the biggest.

Not the most social.

The most personal.

---

# Product Philosophy

Forkprint is not designed to help people find restaurants.

Forkprint is designed to help people remember the restaurants that became part of their lives.

Every feature should strengthen that purpose.

Whenever there is uncertainty about a product decision, ask a simple question:

> "Will this help someone remember or rediscover a meaningful food experience?"

If the answer is no, it probably does not belong in Forkprint.

---

# Core Principles

## 1. Offline First

Forkprint should remain fully functional without an internet connection.

The application should never depend on cloud services for its core experience.

Internet should enhance the application.

It should never be required for the application to remain useful.

If every online service disappeared tomorrow, Forkprint should still continue serving its primary purpose.

---

## 2. AI Enhanced

Artificial Intelligence is a companion.

It is not the product.

AI should help users understand their food history.

AI should provide insights.

AI should summarize.

AI should recommend.

AI should answer questions.

But AI should never become a dependency.

If AI is disabled completely, Forkprint should still function as an excellent product.

---

## 3. Privacy by Default

Users should never feel like they are the product.

Forkprint should collect only the information necessary to deliver its features.

No unnecessary tracking.

No unnecessary analytics.

No mandatory accounts.

No advertisements.

No selling user data.

The user's memories belong to the user.

Always.

---

## 4. User Ownership

Everything created inside Forkprint belongs to the user.

Users should always be able to:

* Export their data
* Import backups
* Delete everything
* Leave the platform

No vendor lock-in.

No hidden formats.

No barriers.

Forkprint earns trust by respecting ownership.

---

## 5. Memory Over Businesses

Restaurants are not the center of the application.

Visits are.

A restaurant is simply a location.

A visit is a memory.

Every important feature should revolve around visits rather than businesses.

The application should tell stories about people's experiences rather than describing restaurants.

---

## 6. Calm Software

Forkprint should feel peaceful.

Avoid unnecessary notifications.

Avoid addictive mechanics.

Avoid engagement hacks.

Avoid endless feeds.

Avoid dark patterns.

The application should invite people to revisit memories, not demand their attention.

Good software respects a user's time.

---

## 7. Simplicity Before Complexity

Every feature should solve a real problem.

Avoid building features because they are technically interesting.

Prefer fewer polished experiences over many unfinished ones.

Complexity should only be introduced when it clearly improves the user experience.

---

## 8. Build for Years

Engineering decisions should prioritize long-term maintainability over short-term speed.

Write code that future contributors can understand.

Document architectural decisions.

Prefer clean abstractions.

Avoid shortcuts that create future technical debt.

Assume Forkprint will still be actively developed five years from today.

Build accordingly.

---

# Design Philosophy

Forkprint should feel personal.

Not corporate.

Not noisy.

Not overwhelming.

The interface should encourage reflection.

Every screen should communicate one feeling:

"These are your memories."

---

# AI Philosophy

Artificial Intelligence should never replace the user's memories.

Instead, AI should help reveal patterns that would otherwise remain hidden.

Examples include:

* Weekly summaries
* Food stories
* Trip recaps
* Taste evolution
* Personal recommendations
* Natural language search
* Memory resurfacing

The AI should feel like a thoughtful companion reading a personal journal.

Not a chatbot.

---

# Engineering Philosophy

Every engineer contributing to Forkprint should behave like a long-term owner rather than a temporary contributor.

Before implementing any feature, understand the existing architecture.

When multiple solutions exist:

Choose the solution that is:

* Easiest to maintain
* Most consistent with the project philosophy
* Most respectful of user privacy
* Most resilient offline
* Most extensible for future development

Never sacrifice architecture for speed.

Never duplicate logic unnecessarily.

Always leave the repository cleaner than you found it.

---

# Product Test

Before adding any new feature, ask the following questions:

1. Does this help users remember something meaningful?

2. Does this respect user privacy?

3. Does this still work without internet whenever possible?

4. Does this improve the experience rather than simply adding functionality?

5. Would we still build this feature five years from now?

If multiple answers are "No", reconsider the feature.
